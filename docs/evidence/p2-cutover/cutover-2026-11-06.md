## Finding: the distro stopped when no SSH session held it

`last` showed distro boots at 14:47, 14:50, 14:55, 15:02 and 15:07. The Windows task "Jorah WSL" had last run at 08:51 with result 1: its `sleep infinity` ended when the distro was restarted during setup, and a boot trigger doesn't rerun. The Gateway stopped cleanly with each shutdown (SIGTERM from systemd at 15:06:06).

Fix, on Adam's yes: the task was started again, `openclaw-gateway.service` enabled, and a second trigger added that repeats every 5 minutes, indefinitely. `MultipleInstances: IgnoreNew` makes it a no-op while the keep-alive runs. Measured afterwards: task `Running`, triggers `MSFT_TaskBootTrigger` and `MSFT_TaskTimeTrigger every=PT5M`, principal unchanged (`adamh`, S4U), the keep-alive's PID and the Gateway's start time unchanged.

## Finding: Jorah had no tools

`What do you remember from the Mac?` at 15:12 got `Working` and no answer. Claude Code reaches OpenClaw's tools through a loopback MCP server in the Gateway (`mcp.json`: `http://127.0.0.1:45030/mcp`). OpenClaw 2026.10.9 always starts it on port 0, a random port, with no setting. The firewall allowed only 43181-43199 and 43210 on loopback, so `curl` as `jorah` was refused at once and the loopback reject counter rose from 0 to 8. The 15:05 heartbeat's garbled Telegram message (a tool call written out as text) fits the same cause. The rehearsal never ran a model turn, so it couldn't show this.

`net.ipv4.ip_local_port_range` is `43255 47350`, set by WSL. Windows listeners between 40000 and 49999: Sunshine on 47984-48010, Tailscale on 41344, and one `::1` port at 42050, none inside the range. Windows' dynamic range starts at 49152, and no exclusion covers the range. On Adam's yes, `deploy/jorah-firewall.nft` allows 43255-47350 on loopback for `jorah`.

`AdamHikl/merlin-test-project` had no egress firewall, so it never met this.
