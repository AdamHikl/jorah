## Voice marker (G-S1 follow-up)

Chat Completions turns sent to jorah-dev, with the spike recording what the hook sees as `requester`:

| Request | `requester` |
|---|---|
| As `jorah-voice` sends today | `channel: webchat`, owner, no sender id |
| Plus a `user` field | same |
| Plus `x-openclaw-sender-id` or `x-openclaw-sender-is-owner` | same (ignored) |
| Plus `x-openclaw-message-channel: voice` | **`channel: voice`** |
| Plus `x-openclaw-message-channel: telegram` | **`channel: telegram`**, owner, no sender id |
| An empty channel header | `webchat` |

So `jorah-voice` can mark its turns with one header. But any holder of the Gateway token can claim any channel, Telegram included. The docs already call that token full operator access. **Fixed in the guard:** Adam's own typing is now Telegram *with* a sender id, or the PC's CLI (no channel and no sender id, which Chat Completions can't produce). `voice` and `webchat` count as voice. Any other channel counts as outside text. Real Telegram turns carrying a sender id is still to be confirmed on live (P5.6). If they don't, Adam's Telegram chat would count as outside text, which is the safe direction.
